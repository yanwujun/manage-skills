# Design

## Context

本 change 建立在 `bootstrap-mvp-cli` 的索引与审计之上，并复用 `desktop-app` 的视图框架。标签与相似度都必须满足项目的信任原则：纯本地、零网络、默认不改源文件。相似度计算的输入是技能正文，输出是「组」与「分数」，不自动做任何合并。

## Goals / Non-Goals

**Goals:**

- 标签可持久、可筛选、可批量操作，且与 frontmatter 双向可对照。
- 近似重复检测在 500 份技能规模下可在数秒内完成，且结果可解释（描述与正文分开计分）。
- 忽略规则可持久，避免每次审计都重复提示同一对。
- 计算过程不阻塞界面（桌面端）。

**Non-Goals:**

- 不做语义向量或任何模型推理（零网络、零模型下载）。
- 不做层级标签树。
- 不自动合并或自动删除近似技能。
- 不做跨语言相似（中文与英文技能互不比较相似度结论）。

## Decisions

### D1 标签模型：增量式覆盖

sidecar 为每个技能保存 `tags: { added: string[], removed: string[] }`，有效标签 = `(frontmatter.tags ∪ added) - removed`，全部小写归一。这样手工操作永远可撤销，源文件变化时也能正确重算。备选「直接存最终集合」被否：frontmatter 更新后无法区分哪些是用户加的。

### D2 建议标签：目录与关键词规则

复用分类建议的规则表（目录名、描述关键词），命中即产出 `suggested` 标签，不写入 effective 集合。用户采纳后写入 `added`。

### D3 相似度管线：归一化 → 特征 → MinHash/LSH → 精确 Jaccard

1. 归一化：去 frontmatter、去 fenced code block、去 URL、去标点，统一小写。
2. 特征：英文按词，中文按字符 3-gram；两路合并为一个集合。
3. 候选：MinHash（128 个置换）+ LSH（32 band × 4 row），只对同桶对算精确值。
4. 精算：对特征集合算 Jaccard，作为最终分数。

选 MinHash/LSH 而非直接两两比较：500 份技能两两 12.5 万对，特征集合较大时不可接受；LSH 把候选降到百级。

### D4 描述与正文综合的方式

先把描述重复 k 次（默认 k=2）再与正文拼接，作为同一份文本参与特征提取。备选「分别算分再加权」被否：两套特征集合会让 MinHash 逻辑复杂一倍，而重复描述已能达到「描述权重更高」的效果。k 可配置。

### D5 阈值：高置信 0.8 / 展示 0.6

`similarity.json` 与审计只用 ≥0.8 的高置信组；界面可展示 ≥0.6 的候选并按分数排序。阈值存 `config.json`，调整后下次计算生效。阈值是经验值，设计上不追求「绝对正确」——界面同时展示描述/正文分项，让用户自行判断。

### D6 缓存与失效

相似组结果写入 `~/.manage-skills/similarity.json`，记录参与计算的技能内容 hash 集合；索引刷新后若集合变化，标记为脏并在下次进入视图/审计时重算。

### D7 分组：并查集 + 链式标注

将分数 ≥ 展示阈值的对用并查集合并成组；组内若存在非全互连（A~B、B~C 但 A!~C），在数据中标记 `chained: true`，界面提示「组内并非全部两两相似」。

### D8 忽略规则

忽略记录为无序对 `{ a: id, b: id }`，以两 id 排序后哈希作键，存 sidecar。计算后过滤掉被忽略的对；若一个组因忽略而只剩一个成员，则该组不展示。

### D9 执行位置：core 纯函数 + 桌面端 Web Worker

相似度是 CPU 密集型纯计算，放在 `src/packages/core` 的纯函数中；桌面端通过 Web Worker 调用，避免阻塞渲染。索引与缓存读写由调用方注入。

### D10 界面：标签面板 + 相似组视图

标签面板位于技能列表工具栏下方（可折叠），显示标签与计数；相似组视图复用卡片组件，组卡片展开后显示两两分数条（描述/正文分段）与操作按钮。全部样式走既有 CSS 变量。

## Risks / Trade-offs

- **短文本误报**（几十字的技能）→ 正文特征数低于下限时降低权重或标注「样本过短」，不参与高置信结论。
- **模板化技能**（大量样板段落）→ 代码块与固定标题过滤，必要时按段落去重后再提特征。
- **中文分词不可用** → 字符 3-gram 不依赖分词器，代价是特征维度略高，由 MinHash 化解。
- **MinHash 漏报** → LSH 只影响候选，精算 Jaccard 兜底；漏报可通过调高 band 数缓解（配置项）。
- **阈值主观** → 可配置 + 分项分数展示；不做「自动合并」避免误伤。
- **500 份计算耗时** → Web Worker + 缓存；超过预算时降低 MinHash 置数或增大 LSH 桶宽。

## Migration Plan

`index.json` 的 `schemaVersion` 升级，新增 `tags` 字段；旧索引在首次加载时按「frontmatter 重新解析 + 空增量」迁移，不丢数据。`similarity.json` 为新增缓存文件，可不迁移。回滚：删除 `similarity.json` 与 tags 字段即可，源文件始终未改动。
