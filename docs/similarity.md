# 相似度检测

在本地发现「内容相近但不是完全相同」的技能——改名副本、微调版本、同模板复制。纯本地计算，不调用任何模型或网络接口。

## 算法

1. **归一化**：去掉 frontmatter、代码块、URL 与标点，统一小写，只保留中英文正文
2. **特征**：英文按词（长度 ≥3），中文按字符 3-gram；描述内容按权重 2 合并，提升其影响
3. **候选**：MinHash（64 置换）+ LSH（16 band × 4 row），只对同桶对做精算
4. **判定**：加权 Jaccard（Σmin / Σmax）
   - ≥ 0.8：高置信近似重复，进入审计报告
   - 0.6 ~ 0.8：在界面中按分数展示
   - < 0.6：不展示
5. **分组**：并查集合并相似关系；组内并非全部两两相似时标记 `chained`

## 在审计中查看

```bash
npx manage-skills scan
npx manage-skills audit
```

报告会包含 `similar` 类别：

```text
## [similar] 近似重复：alpha / alpha-v2

2 份技能内容高度相似（最高 92%）
- alpha（claude-code · claude）hash=… size=… mtime=…
- alpha-v2（claude-code · claude）…
- 相似度：92%

建议：对比后保留一份；确认不是重复可标记为忽略
```

默认脱敏：报告只输出组、分数与来源，不输出技能正文。

## 忽略规则

把某一对标记为「不是重复」后，后续计算不再提示该对：

- 忽略记录以两个路径排序后的组合为键
- 通过 core API 传入 `ignoredPairs` 即可生效；桌面端会把忽略记录持久化
- 撤销即从忽略列表中移除，该对重新参与计算

## 缓存

- 计算结果写入 `~/.manage-skills/similarity.json`
- 缓存的 `sourceDigest` 由所有技能的「路径 + 内容 hash」生成
- 任一技能内容变化 → digest 变化 → 下次自动重算

## 性能

500 份平均 4KB 的技能，全量计算实测约 1.3 秒（预算 5 秒）。LSH 把候选对压到百级，避免 12.5 万次两两精算。

## 局限

- 词法相似：语义相近但用词完全不同的技能不会命中（v2 再考虑本地向量）
- 短文本（几十字）特征过少，可能误报或漏报
- 代码块被排除，只比较说明性文字
